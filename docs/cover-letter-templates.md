# 求職信底稿

求職信頁面可建立與選擇底稿。同一份履歷投遞不同職缺時，第一、二、四段使用已確認的文字，AI 只生成第三段。適用各種職種；第二段可寫工作、作品、研究或專案經驗。

## 使用方式

1. 先生成並修改第一封信，按「用這封信建立底稿」，帶入目前編輯的一、二、四段；也可開啟「已有自己的內容？自行建立底稿」自行填寫。帶入不會呼叫 AI 或立即寫入資料庫。
   已知的完整公司名稱與職稱會轉成替換符號，請確認其他公司專屬描述也已移除；若第一段缺少替換符號，頁面會提示補上。沒有分段資料的舊信需自行分段貼入。
2. 第一段須包含 `{{company}}` 與 `{{job_title}}`，生成時由程式替換。
3. 核對事實後按「確認並儲存新底稿」，再按重新生成。
4. 修改底稿後再次儲存會建立新紀錄，舊底稿與舊求職信不變。
5. 履歷原文或解析內容變更時，舊底稿會標記過期；核對後另存新底稿才能再次使用。

未選底稿時仍使用原本的整封生成流程。底稿只在相同使用者與同一份履歷的職缺比對間共用。生成結果保留底稿快照；Reviewer 會提出檢查結果，但不自動改寫固定段落。固定不等於內容已被驗證，仍須確認使用者填寫的事實與 AI 生成的第三段。

## 開發與部署

更新程式後，先對目標資料庫執行 `alembic upgrade head`，新增 `cover_letter_templates` 資料表。務必核對 `DATABASE_MIGRATION_URL`（未設定時使用 `DATABASE_URL`）指向的環境。

- GET `/cover-letter-templates?matching_id=...`：列出可用底稿與過期狀態。
- POST `/cover-letter-templates`：確認並新增不可覆寫的底稿。
- POST `/cover-letters/generate`：可選傳入 `template_id`；語言需與底稿一致。

整合測試使用隔離的測試資料庫 schema 與模型替身，不呼叫付費模型。實際語氣與內容品質仍需以真實履歷、職缺進行人工驗收。Demo 帳號不包含在本次功能內。
